# 使用指南

## 启动应用

开发模式需要同时启动本地 API 和桌面端。完整环境要求与命令见项目根目录 README。

1. 启动指纹浏览器服务（BitBrowser 或 AdsPower）。
2. 启动后端：`PYTHONPATH=backend uv run python -m app.run`。
3. 在 `apps/desktop` 启动桌面端：`pnpm tauri dev`。
4. 打开任务页，选择任务模块、浏览器供应商和运行配置。

## 配置与资料

任务模块通过 manifest 定义配置项和资料类型。带资料类型的必填字段必须至少有一条可用资料，才能创建运行。

- 在任务配置页填写任务参数并保存。
- 在资料区域录入或导入资料；敏感信息不要写入插件源码。
- 资料由任务领取后，只有任务确认完成时才应标记为 `used`；失败或取消的资料应被释放以便重用。

## 运行任务

1. 选择并发数和浏览器清理策略：`keep_open`、`close` 或 `delete`。
2. 点击启动。一个运行会拆为多个工作项，并按并发数执行。
3. 在运行详情查看实时日志、浏览器会话、结果和附件。
4. 如需中断，使用停止按钮；可选择是否强制清理浏览器。

## 人工处理提醒（Turnstile 等）

当插件需要人工介入时，它会通过独立通知通道提醒桌面端，而不是把提醒混进日志流。通知包含：

- `ding.wav` 提示音；
- 中文 TTS 文案，例如“窗口 1 需要处理人机验证”；
- 桌面内持续 30 秒的提示条。

请保持 Nexus Flow 窗口运行且系统声音未静音。启动任务的点击动作会预先解锁浏览器音频权限。

### overchargedforpork 的 Turnstile 处理

该任务打开 Claim 页面后，若 5 秒内没有检测到 `#ClaimForm`，会判定可能正在等待 Turnstile：

1. 前端播放提示音并朗读需要处理的浏览器窗口编号。
2. 在对应浏览器窗口完成 Turnstile。
3. 页面出现 `#ClaimForm` 后，通知自动解除，任务继续填写。
4. 若在剩余等待时间内仍未出现表单，工作项会失败并留下超时日志。

通知是运行时内存状态；后端重启会清除尚未解决的通知。

## 常见问题

**没有声音**：确认系统未静音、Nexus Flow 窗口仍在运行，并先通过“启动任务”完成一次用户手势授权。

**浏览器没有执行操作**：确认任务使用的浏览器会话的调试地址可连接，并检查运行日志中的 DrissionPage 连接和元素校验错误。

**资料被错误占用**：先停止运行，检查对应工作项是否成功完成；只有业务流程完成后才应将资料标记为已使用。
